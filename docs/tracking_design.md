# 航迹关联设计说明

把每次估计输出的一组**已排序角度**串成带稳定编号的航迹：新目标
出现、确认、暂时丢失、终止都由服务明确告知上位机；估计结果里的每个
角度注明归属；最难的“两目标交叉、谱上只剩一个峰、MDL 少报一个源”
期间不判丢、不并轨、编号随运动方向走。

航迹功能挂在会话上，建会话时通过 `tracking.enabled` 开关；不开的
会话行为与旧版完全一致。

---

## 1. 数据模型与生命周期

```
tentative（候选） ──连续命中 3 拍──▶ confirmed（确认）
tentative         ──连续 2 拍没关联上──▶ terminated（终止）
confirmed         ──连续 3 拍没关联上──▶ lost（暂时丢失）
lost              ──重新命中──▶ confirmed（track_reacquired）
confirmed / lost  ──连续 6 拍没关联上──▶ terminated（终止）
```

门限（单位＝一次估计/一批，定义在 `app/tracker/tracker.py`）：

| 常量 | 值 | 含义 |
| --- | ---: | --- |
| `CONFIRM_HITS` | 3 | 连续 3 拍关联上才确认；**一闪而过的假峰最多 1 个点，永不确认** |
| `TENTATIVE_MAX_MISSES` | 2 | 候选出生后再连续 2 拍不见即终止（出生当拍是命中，不计丢失） |
| `LOST_AFTER` | 3 | 确认目标连续 3 拍不见才算“暂时丢失” |
| `TERMINATE_AFTER` | 6 | 连续 6 拍不见才终止 |
| `GATE_DEG` / `LOST_GATE_DEG` | 3.5° / 8° | 关联门，丢失后重获放宽 |

航迹历史点**只记录真实归属到的测量角**（带 version、angle、power），
不写预测点、不事后改写：交叉保持期间历史出现空洞，恢复后续接，
这正是“在交叉附近先不归属、等分开后再认定”和“已推给上位机的归属
不回头改”两条要求的直接体现。

事件类型：`track_appeared`、`track_confirmed`、`track_lost`、
`track_reacquired`、`track_terminated`，外加交叉机制的
`crossing_started` / `crossing_resolved` / `crossing_force_released`。
每个事件带产生它的估计 `version`。

## 2. 常规更新：预测 + 全局最近邻

每来一次估计（角度 + 逐角功率）：

1. **预测**：航迹速度由最近 5 个历史点做最小二乘（度/每次估计），
   从最后命中位置外推一拍。
2. **门限内代价**：`代价 = |测量角−预测角| + 0.2·|ln P测 / P轨|`，
   功率只作角距离的次级微调；代价全局排序后贪心分配（同一会话目标
   数很少，≤6 个量级，贪心在门限+交叉特判覆盖下与匈牙利解等价）。
3. 没分到测量的航迹计一次未命中；没分到航迹的测量生成候选航迹。
4. 新候选还要过一道**弱峰闸**：功率低于现存航迹最大功率 0.2 倍的
   孤立峰不生航迹（交叉附近 ±28° 的 MUSIC 旁瓣假峰功率很低，
   连候选都不会生成）。

逐角功率不能用引擎里的 `signal_power_est`——它按特征值降序排，与
角度没有对应关系。`app/doa/beamform.py` 新给了一个归一化常规波束
输出 `P(θ)=a(θ)ᴴRa(θ)/M`，对分开的源与真实功率单调对应。

## 3. 交叉处理（本设计的核心取舍）

### 3.1 观测事实（M=8、K=50、SNR 15 dB、两源 1:0.5，固定种子）

剧本里两源以约 0.77°/拍相向，瑞利波束宽 ≈10.2°：

* 交叉中心前后（夹角 <1° 两拍）**MDL 只报 1 个源**，谱上是一个峰；
* 再往外几拍（夹角 ≈1.5–4°）MUSIC 第二峰跑到 **±28° 的旁瓣假峰**，
  与两目标真实位置差 25° 以上；
* 夹角 ≥4° 后两峰恢复干净，此时按各自速度外推，归属毫无歧义。

### 3.2 选定的办法：成组保持（coasting）＋按运动趋势解组

成组触发（只对 confirmed 航迹、并查集聚类，二选一）：

* 两条航迹的一步预测间距 ≤ **2.5°**；或
* 间距 ≤ 6° 且在相向运动、同时组邻域（中点 ±6°）内的测量数少于
  航迹数——即“靠近 + 已经少报”，提前一拍进入保持。

保持期间：

* 组成员**不参与普通关联、不计未命中**（所以不可能被判丢失）；
* 组邻域内的测量**不归属、不生成新航迹**（旁瓣假峰被隔离，不会
  并轨也不会偷号）；
* 每条航迹在内存里按自己的速度继续外推（不落历史、不外发）。

解组条件（必须同时满足，遍历成员↔测量的全部排列取最优）：

1. 每个成员都在 3.5° 门内找到自己的测量；
2. 测量彼此分开 ≥ **2.5°**（峰确实重新分开了，杜绝假峰凑数）；
3. **防互换裕量**：分给我的测量，距我的预测必须比分给组内任一
   其他成员近至少 **1°**（两轨夹角 × 速度符号不发生交换）；
4. 功率对数差作为排列同分时的次级排序（1 与 0.5 在分开段分得开）。

条件不满足就继续等，上限 `MAX_GROUP_HOLD=12` 拍，仍解不开才
强制释放并交回普通门限（发 `crossing_force_released`）。剧本中
保持约 4 拍、远小于兜底上限。

### 3.3 为什么选它，放弃了什么

* **放弃“纯功率对号”**：交叉时两方向图几乎重合，任何波束功率在
  交点都不可分；功率只在两峰重新分开后有区分力，所以只把它放在
  解组的次级排序和生候选的弱峰闸里。
* **放弃“强行把唯一峰关联给某一条/两条共用一个测量”**：唯一峰
  既不代表任一源的真实角，共用测量又会在两条历史里各留一个错点；
  本方案在该区间干脆不给归属（需求明确允许），用速度外推维持
  编号连续性。
* **放弃 JPDA/多假设跟踪等概率方案**：它们需要过程噪声、检测概率、
  杂波密度等调参模型，而我们的“杂波”主要是确定的 MUSIC 旁瓣，
  测量是每批独立噪声下的独立估计（没有平滑协方差），概率模型的
  假设并不更贴；确定性规则可复现、可逐拍解释、重启逐位一致，代价
  是门限是按当前规模（ULA ≤64、批级估计、个位数目标）手调的。
* **代价**：交叉期间上位机拿不到这两条航迹的角度归属（持续约
  4/40 批）；交叉期间恰好新出现的真实第三目标，若落在组邻域内，
  要等到解组后才会被重新发现。
* **会认错的条件**：
  - 两源交叉时**速度也几乎相同**（交叉后不分开）或长时夹角
    2.5–4° 徘徊超过 12 拍：兜底强制释放后靠 8° 宽门重获，极端
    情况下编号可能互换；
  - 外推期间目标自己突然转向（交叉中心处加速度很大），外推失效；
  - 一帧之内同时发生多个交叉、第三目标恰从交叉点中穿过，规则
    未做联合分辨；
  - SNR 比验收更低导致分离后角度抖动仍 >3.5° 或假峰功率不再是
    “弱峰”时，解组时机会推迟（不并轨，但归属空洞变长）。

## 4. 持久化、重启一致性、并发

* `state.json` 新增 `tracker` 段（全部航迹、下一个编号、交叉组的
  成员/外推角/已保持拍数），随累加器状态一起**原子替换**；
  航迹事件追加写 `track_events.jsonl`（每行带 version）。
* 关联器是**纯确定性**的：输入（version、角度、功率）相同则输出
  逐拍相同，不读时钟、不依赖随机数；时间戳只在会话层补进事件。
  因此中途重启后续推，航迹编号、历史点、每拍归属与状态变化和
  “一口气跑完”**逐项一致（时间戳除外）**——见
  `test_restart_midway_matches_uninterrupted_run` 与专门在
  MDL 少报区间内重启的 `test_restart_inside_crossing_keeps_identity`。
* 每会话一把可重入锁：并发追加 + 估计在锁内串行，航迹更新顺序
  与估计的实际处理顺序严格一致；估计 version 单调、一次估计只
  关联一次；重复 `batch_id` 整批跳过（连带不产生估计、不产生
  任何航迹事件）。
* 事件按 version 轮询（`GET .../track-events?since_version=N`），
  JSONL 追加写保证不漏；分页严格 `version > since` 保证不重。

## 5. 接口（全部为新增字段/新增端点，旧字段不动）

* 建会话：`tracking: {"enabled": true}`。
* 每次估计信封新增 `tracking`：`assignments`（逐角：track_id/
  associated）、`tracks`（快照）、`events`、`crossing`。
* `GET /sessions/{id}/tracks`（列表，可 `include_terminated=false`）、
  `GET /sessions/{id}/tracks/{tid}`（含完整 history）、
  `GET /sessions/{id}/track-events?since_version=N`。
* 会话状态新增 `tracking_enabled`、`n_tracks`。
* 未开航迹的会话：响应字段一个不多，`track_events.jsonl` 文件都不
  建；升级前的旧会话目录无该文件/无 tracker 状态，照常加载与追加。
